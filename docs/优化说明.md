# 优化说明：从 PowerShell 脚本到原生应用

本文记录 `Hyruty/Cleaner`（上游）与本项目（2.0.2）之间的差异，以及重写过程中
遇到的两个真实缺陷。结论先行：

* 清理范围与安全边界**保持不变**（同一份白名单思路，更严格的路径校验）。
* 实现方式由「1,918 行 PowerShell 脚本 + 两个 .cmd 启动器」换成
  「约 8,500 行 C#（主程序约 6,200 行 + 安装程序约 2,300 行），单个 exe，无脚本宿主」。
* 新增安装 / 卸载 / 升级、双语、并行扫描、可取消、可自检、可截图、静默部署。

---

## 1. 上游结构

```
Cleaner/
├─ CDriveCleaner.ps1          1,918 行：参数、白名单、扫描、删除、回收站、计划任务、WinForms UI
├─ strings.zh-CN.json         外部语言文件
├─ Start-CDriveCleaner.cmd    隐藏窗口启动 powershell.exe -File
├─ Remove-AutoClean.cmd       卸载自动清理任务
├─ Update-InstalledVersion.cmd 复制脚本到固定目标目录（硬编码 D:\Code\...）
└─ person_icon.ico            178 KB 图标
```

上游的工程质量其实不错：有 `-SelfTest` / `-DryRun` / 截图模式、有受保护路径校验、
有跳过重解析点、日志按 30 天清理。主要问题不是"写得差"，而是**形态限制**：

| 问题 | 后果 |
| --- | --- |
| PowerShell 解释执行 + `DoEvents` 刷新 | 首次扫描慢、界面"假死"，无法中途取消 |
| 扫描在 UI 线程 | 大目录（浏览器、`npm-cache`）卡住数秒 |
| 依赖执行策略 | 企业策略禁止脚本时无法运行 |
| 外部 `strings.zh-CN.json` | 缺文件即无界面文案；只有一种语言 |
| 自动清理依赖"把脚本复制到 engine 目录" | 升级后引擎可能与界面版本不一致 |
| 无安装包 | 只能解压运行，没有卸载入口、快捷方式、ARP 条目 |
| PowerShell 字符串格式化 | `-f` 与 JSON 维护成本高，异常路径易吞错 |

## 2. 逐项对照

### 2.1 运行时与分发

| | 上游 | 本项目 |
| --- | --- | --- |
| 入口 | `Start-CDriveCleaner.cmd` → `powershell.exe -File` | `Cleaner.exe`（WinExe，AnyCPU） |
| 依赖 | PowerShell 5.1 + 执行策略允许 | .NET Framework 4.8（Win10 1903+ 自带） |
| 文件数 | 4 个（ps1 + 2 cmd + json） | 1 个 exe（语言内置） |
| 启动开销 | PowerShell 冷启动 + 解析 1,900 行 | 原生加载，直接显示窗口 |
| 安装 | 手动解压 | `CleanerSetup.exe`：安装 / 升级 / 静默 / 卸载 |

### 2.2 扫描与清理

| | 上游 | 本项目 |
| --- | --- | --- |
| 并发 | 串行，逐类别 | 类别级并行，`SemaphoreSlim` 限制为 `min(4, CPU)` |
| 取消 | 无 | `CancellationToken`，「取消」按钮即时生效，删除阶段逐项检查 |
| 进度 | 每项完成后 `DoEvents` | `IProgress<T>` 回报到 UI 线程，状态栏 + 进度条 + 逐行更新 |
| 枚举 | `File.GetAttributes` 逐项额外系统调用 | `DirectoryInfo.EnumerateFileSystemInfos()` 复用 `FindFirstFile` 缓存 |
| 长路径 | 受 `MAX_PATH` 限制 | 所有 IO 走 `\\?\` 前缀（UNC 转 `\\?\UNC\`） |
| 删除重试 | 只清只读属性 | 清 `ReadOnly/Hidden/System` + 120 ms 后重试一次 |
| 跳过记录 | 最多 200 条样本 | 同样 200 条，写入日志并在结果框提示数量 |
| 回收站 | shell API + 文件系统兜底 + 计数校验 | 相同策略，抽成 `RecycleBin` 类，兜底按 SID 目录清理 |

### 2.3 界面

| | 上游 | 本项目 |
| --- | --- | --- |
| 主题 | 白底 + 深色页眉 | 渐变页眉、圆角卡片、自绘按钮/进度条，跟随 DPI 缩放 |
| 语言 | zh-CN | zh-CN / en-US，可切换（重启生效），支持 `lang.<culture>.json` 覆盖 |
| 列宽 | 固定 280/140/440 | 按实际字体测量（DPI 感知），说明列自适应填充 |
| 状态反馈 | 状态标签 | 状态标签 + 进度条 + 每行"扫描中…/需要管理员/请先关闭浏览器" |
| 结果 | MessageBox 纯文本 | 结果对话框：大号释放量、文件/文件夹数、跳过原因、"打开日志" |
| 窗口记忆 | 无 | 记住大小、位置、最大化状态与勾选状态 |
| 单实例 | 无（可开多个） | 命名互斥量 + 事件唤醒已有窗口 |

### 2.4 自动清理

## 3. 重写中修复的四个真实缺陷

### 3.1 CLR 传统路径模式吞掉深层缓存

`csc` 直接编译（不经 MSBuild）时不会自动生成
`[assembly: TargetFramework(".NETFramework,Version=v4.8")]`。
缺少该特性时，.NET Framework 4.8 的 CLR 会把进程当成"老应用"，启用
`Switch.System.IO.UseLegacyPathHandling`，于是 `\\?\C:\...` 被判定为"路径中具有非法字符"：

* 扫描：枚举抛异常 → 该类别记 1 个错误、体积 0（用户看到"未发现缓存"）；
* 删除：`File.GetAttributes` 抛异常 → 记一次跳过。

自检最初正是这样暴露出来的（`scanner.measures`、`deleter.safe-tree` 失败，
错误信息为"路径中具有非法字符"）。修复即在 `AssemblyInfo.cs` 增加该特性，
同时把 `PathSafety.Normalize` 里的扩展前缀剥离，保证路径比较与显示一致。

### 3.2 单文件统计用了赋值

`FileScanner.MeasureFile` 最初写成 `stats.Files = 1; stats.Bytes = info.Length;`，
在"目录内容"模式下逐个文件统计时，后一个文件会覆盖前一个：

* 4 个 25 字节文件只会显示 25 B / 1 个；
* 上游用 `$state.Bytes + ...` 累加，本重写时引入的回归。

修复为 `++` / `+=`，并新增"扁平目录 4 个文件 = 100 B"的断言防止回归。

### 3.3 提权重启被自己的单实例锁挡住（2.0.1）

「以管理员身份重启」在 2.0.0 上表现为：窗口关闭，但没有新的（管理员）窗口出现。
日志给出了答案：

```
13:07:03 [INFO] Starting UI (admin=True)
13:07:03 [INFO] Another instance is already running; activation signal sent.
```

提权进程**确实启动成功**（`admin=True`），但它启动时旧进程还持有
`Local\Cleaner.App.SingleInstance` 互斥量，于是新进程认为"已有窗口在运行"，
发了个唤醒信号就退出；与此同时旧进程正在关闭。两边一让一退，桌面上什么都没有。

修复分两层：

1. 旧实例在新的（提权）进程启动成功后**先释放互斥量**再关闭（`MainForm.Elevating` 事件），
   新进程一般可以立刻拿到所有权；
2. 新进程带 `--handoff` 启动，若发现互斥量被占用，最多等待约 22 秒逐次尝试接管
   （`SingleInstance.TryTakeOwnership`，并处理旧进程崩溃留下的 `AbandonedMutexException`），
   超时则写日志退出，不会造成"静默消失"。

同时修正了参数拼接：原本对以反斜杠结尾的值（如 `C:\Users\x\AppData\Local\`）
没有把结尾反斜杠翻倍，结尾引号会被当作转义引号吞掉。已按 CRT 规则重写，并用
.NET Framework 真实解析器验证（中文、空格、内嵌引号、结尾反斜杠共 7 组用例）。

### 3.4 结果对话框在高 DPI 下挤压重叠（2.0.2）

用户截图里「清理完成」对话框文字互相覆盖、底部按钮完全看不见。原因是
`ResultDialog` 只设了 `AutoScaleMode = Dpi`，却漏了 `AutoScaleDimensions`：
窗口保持 520×340 的 96 DPI 尺寸不缩放，而字体是按 DPI（150%）放大的，
于是 28pt 的释放量压住三行摘要，详情块又压住按钮区。

修复：

* 补上 `AutoScaleDimensions = (96, 96)`，让窗口随 DPI 放大（560×438 → 840×657）；
* 布局改成 `TableLayoutPanel`：大号数值／摘要／详情／按钮各占一行，详情行自适应剩余高度，
  长文本自动换行，不再依赖魔法坐标；
* 新增 `--screenshot-result <png>`，用样例数据渲染该对话框，便于回归验证
  （见 `docs/images/result-zh.png`、`result-en.png`）。

## 5. 仍然保留的上游优点

* 白名单 + 受保护目录的思路（改为集中式目录 + 二次校验）。
* "跳过而不是强删"的删除哲学。
* 关机触发 + 登录补做的计划任务模型。
* 日志按天命名、按 30 天清理。
* `-DryRun` / `-SelfTest` 这类可验证性设计（扩展为 5 种模式）。
